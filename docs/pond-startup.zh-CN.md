# 池塘启动耗时与渲染配置

池塘通过 `src/renderer/ui/fishing.ts` 单独指定 Ruffle 的 `preferredRenderer: 'webgl'`，减少默认 wgpu/WebGL 路径初始化着色器管线造成的停顿。配置只传给本次池塘播放器，不改全局 Ruffle 设置，不保留关闭后的播放器，也不提前运行池塘或写入真实存档。

## 本机测量

2026-11-11，在 Windows、Electron 44.10.0、800 × 600 的隔离离屏窗口中，用空测试池塘比较修改前的 `464d26d` 与本次代码。首次测量前没有在该渲染进程中创建其他播放器，随后关闭并重复打开两次；每次协议回调就绪后继续观察 650 毫秒。

| 指标 | 修改前 | 修改后 |
| --- | --- | --- |
| 首次打开至协议回调就绪 | 682 毫秒 | 442 毫秒 |
| 两次重复打开至协议回调就绪 | 298、297 毫秒 | 98、108 毫秒 |
| 首次打开期间最长长任务 | 480 毫秒 | 225 毫秒 |
| 两次重复打开期间最长长任务 | 150、158 毫秒 | 未观察到达到 50 毫秒的长任务 |

修改前的另一次 CPU 采样中，热点集中在 WebGL 程序及着色器状态查询，并出现 wgpu 管线创建调用。直接 WebGL 路径的试验与最终代码均减少了这部分等待；首次初始化仍存在停顿，不能表述为完全无卡顿。

以上是本机隔离测量，不是统计性能承诺。协议回调就绪不表示背景、宠物、鱼和所有动画均已绘制完成。真实应用中已有的宠物播放器、显卡、驱动、缓存和其他负载会影响结果；本次未覆盖所有显卡、操作系统或 Android 设备。已核对池塘鱼卡、字体、透明背景、数量箭头及支付确认的实际渲染，并运行投放流程回归。

## 复测

在仓库根目录执行：

```bash
npm run build
npm run test:ui -- fishing-startup fishing
```

独立 Electron 测试运行时的配置见[开发指南](development.zh-CN.md#检查与测试)。测试使用模拟存档，不操作正在运行的宠物或物理鼠标。

`dist/fishing-startup-results.json` 记录每次打开的同步耗时、协议回调就绪耗时、长任务和最大帧间隔，不设跨机器的固定耗时断言。修改前后的环境和观察窗口应保持一致，不能用一次测量代表全部设备。
